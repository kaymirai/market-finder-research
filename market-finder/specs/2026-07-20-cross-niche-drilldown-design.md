# クロスニッチ段階探索 設計

## 目的

競合が多く直接は狙えない一方で、複数の商品が売れている市場を「探索用親市場」として残す。売れ筋商品のタイトルとEtsy関連語から交差軸を取り出し、需要を保ちながら競合が下がる子キーワードを最大2階層まで探す。

この機能の点数は最終的な販売保証ではなく、次にeRank・Etsy公式・EverBeeで確認する順番を決める探索優先度として扱う。

## 現在の問題

- `generateFollowUpKeywords()`はEverBee競合6,000件未満だけを派生元にするため、高競合・高売上の親市場を使えない。
- EverBeeの商品別タイトルから売れ筋語句を抽出できるが、親市場との関係と次の調査候補が画面上でつながっていない。
- Etsy関連語は需要と掲載数で評価しているが、親から子への需要維持率・競合減少率を比較していない。
- 無制限に語句を組み合わせると検索回数が増え、需要が消えた超ロングテールを大量に作る危険がある。

## 探索用親市場

次の条件をすべて満たす行を親市場にする。

1. 権利リスクや商品不一致で除外されていない。
2. 競合が次のいずれかに達している。
   - EverBee `Listings Analyzed >= 10,000`
   - Etsy公式 `Listings >= 20,000`
   - eRank `Competition >= 50,000`
3. 販売の広がりが次のいずれかで確認できる。
   - 月間販売がある商品が2件以上かつ合計月販10件以上
   - `Selling Listing Count >= 3`かつ`Total Visible Monthly Sales >= 20`
4. クロスニッチ深度が2未満である。

単一の古いベストセラーだけでは親市場にしない。

## 交差軸の抽出

優先順位は次の通り。

1. 親市場のEverBee商品別タイトルで、複数商品に出現する2〜3語フレーズ
2. 公開12か月以内で販売がある商品に出現するフレーズ
3. Etsy Marketplace Insightsの数値付き関連語
4. すでに調査済みで、親語を含み、親より具体的なキーワード

親市場語と商品語を除いた部分を修飾語として扱う。イベント語は前、人物・趣味などの交差軸は前置きを基本にして、商品語は1回だけ末尾へ置く。

## 親子比較

同じ情報源の親子データがある場合だけ比率を計算する。

```text
競合減少率 = 1 - 子の競合数 / 親の競合数
需要維持率 = 子の検索数 / 親の検索数
効率改善倍率 = (子の検索数 / 子の競合数) / (親の検索数 / 親の競合数)
販売維持率 = 子の月販売中央値 / 親の月販売中央値
```

情報源の優先順位はEtsy公式、eRankの順とする。EverBeeの競合数は競合減少率に使えるが、Etsy公式やeRankの需要と混ぜて効率改善倍率を計算しない。

### 比較判定

- `有望`: 競合減少率50%以上、需要維持率10%以上、効率改善倍率1.5倍以上。EverBee取得済みの場合は販売商品2件以上も必要。
- `追加確認`: 親子比較が未取得、または上記の一部だけを満たす。
- `需要減少`: 需要維持率3%未満、競合が25%以上減っていない、またはEverBee取得済みで販売商品が0件。

閾値は初期値であり、30日後実績が20〜50件たまってから調整する。

## 探索制御

- 親市場は上位3件まで。
- 1親あたり上位8候補まで。
- 次の調査へ送る候補は合計12件まで。
- 深度は最大2。
- 同じキーワード、商品語の重複、役割矛盾、権利リスク語を除外する。
- 実測済みで`需要減少`になった候補は次階層へ進めない。
- 新しい修飾語がない場合は候補を追加せず終了する。

これにより総当たりではなく、各階層の上位だけを残すビーム探索として動作する。

## 画面

5段目の最終結果の下に「高競合の売れ筋から掘り下げる」を表示する。

- 親市場名、競合、販売商品数、最近販売数を表示する。
- 子候補ごとに探索優先度、修飾語、取得元を表示する。
- 実測済みの子は競合減少率、需要維持率、効率改善倍率、販売商品数を表示する。
- 「上位候補を次の調査へ追加」で2段目の候補へ戻し、通常のeRankから再確認する。
- クロスニッチ点数を最終Opportunity点数として表示しない。

既存の「売れた語句から追加候補」はこの機能へ統合し、低競合の通常派生候補も失わない。

## エラーと不足データ

- 商品別EverBeeデータがない場合は、Etsy関連語と既存の調査行だけで候補を作り「販売根拠未取得」と表示する。
- 親子で同じ需要情報源がない場合は比率を出さず「追加確認」とする。
- 競合が減っただけで検索数がない語を有望扱いしない。
- 取得日が古い行は既存のOpportunity判定と同様、最終推奨へ昇格させない。

## 受け入れ条件

1. EverBee競合43,906件で複数商品が売れる`cat shirt`を探索用親市場として残せる。
2. 単一の古いベストセラーだけの市場は親市場にしない。
3. 売れ筋タイトルから`book club cat shirt`のような交差候補を作れる。
4. 親50,000競合・1,000検索、子5,000競合・200検索を、競合90%減・需要20%維持・効率2倍と計算できる。
5. 競合が減っても需要維持率3%未満の子を有望扱いしない。
6. 深度2の行から新しい子候補を作らない。
7. 5段目で親子比較を確認し、上位候補を通常のeRank調査へ追加できる。
8. 既存のOpportunity、Etsy段階調査、EverBee商品別表示のテストがすべて通る。

## 対象外

- 自動出品、広告出稿、販売保証
- 3階層以上の探索
- 全候補の総当たり検索
- Etsy/eRank/EverBeeの異なる母集団を同一比率として混合すること
