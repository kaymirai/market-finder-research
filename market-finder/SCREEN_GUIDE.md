# Market Finder 画面ガイド

## 全体の流れ

1. Step 1で調査条件を決める
2. Step 2で候補を確認する
3. Step 3でEtsy公式の直近需要と出品数を確認する
4. Step 4でEverBeeの販売実績を確認する
5. Step 5で2つのスコアを比べ、未来デザイナーCSVやEtsyタイトル・タグへ変換する

## かんたんモード

画面上部の調査方法は3つです。

- `自動で探す（おすすめ）`: 通常の5段階フロー
- `CSVから判定`: EverBee/eRankの調査済み表がある時だけ使用
- `SEOだけ作成`: 良いキーワードが決まっている上級者向け

最初は `自動で探す（おすすめ）` を選びます。

Step 1は条件を選ぶだけです。候補は自動で変わります。

押すボタンは次の4つです。

- 1「候補を自動で探す」
- 3「Etsy公式確認を自動実行」
- 4「EverBeeで売上を確認する」
- 5「SEO案を作る」

eRankは通常フローの必須工程ではありません。Etsyの数字が不明、判定境界、関連語不足、季節・国比較、EtsyとEverBeeの矛盾がある時だけ、Step 5の `eRankで追加確認` を使います。

サンプル、JSON、CSV、手入力、細かいチェックは最初は使いません。必要な時だけ `細かい設定を開く` から確認します。

## Step 1 調査条件

ここでは「何の商品を、誰向けに調べるか」を決めます。

- イベントは、北米イベントを月別リストから選べます。
- リストにないイベントは「イベントを手入力する時だけ」に入れます。
- 手入力欄に文字が入っている時は、上の月別リストより手入力イベントを優先します。
- ターゲットは、イベントごとに用意した初期候補です。
- 父の日なら `new dad`、`dog dad`、`bonus dad`、`grandpa` などが出ます。
- ONにしたターゲットだけが、Step 2の候補作成に使われます。
- 年を空欄にすると、年入り候補は作りません。
- 年を入れると、`dad est 2026` のように年が商品価値になる候補も作ります。
- `最初の市場チェック` では、`fathers day shirt` のような年なしの広い語句で売れている商品名やタグを拾います。

### 買い手は誰ですか（8軸の入口）

イベント名から作った語句は、同じツールを使う競合と必ず重なります。重ならないのは「買い手が自分をどう呼ぶか」から作った語句です。`speech therapist` や `nicu nurse` のような語は、カテゴリを辿っても出てこないため、探している人にしか届かない代わりに競合が薄くなります。

思いつかない時は、欄の上のチップから選びます。医療・教育・セラピー・技能職・サービス・家族の立場・当事者・アウトドア・手芸・暮らしの10グループから、毎回別の領域を1つずつ混ぜて12件出します。`別の候補を見る` で次の12件に入れ替わり、すでに選んだ語は出てきません。

チップは `nurse` や `teacher` のような広い語を含みません。`dialysis nurse`、`kindergarten teacher` のように限定した語だけを載せています。広い語は競合が多すぎて新規店では勝てないためです。

選ぶ基準は検索数ではなく **自分が内容を分かるかどうか** です。調査は需要の在り処までしか教えてくれず、刺さる言い回しまでは教えてくれません。前職、趣味、家族、地元のコミュニティに近い領域を優先します。

入れた語には、節目（retirement / first year / graduation）、贈答（gift for / from the team）、名入れ（personalized / custom name）、様式（retro / vintage）が自動で掛け合わされます。`その人たちの行動・場面` に `squad` や `era` のような言い回しを足すと、さらに内輪の表現に近づきます。

### 今月の探索モード

条件画面では、出品実績に合わせて次の3モードを手動で選びます。

- `市場分散`（M1〜M2）: 新しい市場を100%探索
- `併用`（M3〜M4）: 新市場60%・反応市場40%
- `勝ち市場深掘り`（M5以降）: 新市場30%・反応市場70%

Etsy Statsから推奨モードが表示されても、現在の手動選択は自動で変わりません。

### 時期ゲートから複数角度探索まで

1. `イベント` と `商品種` を選びます。
2. 条件画面の時期判定で、需要ピーク日と残り日数を確認します。45〜75日前だけが自動調査できる時期です。
3. 時期外でも調べる必要がある場合だけ、`このイベントを続けて調査する` を押します。押さない限り自動検索は始まりません。
4. `勝ち候補を探す` を押します。選んだイベントは固定され、他のイベントへ自動では移りません。
5. `探索角度` レールで、需要周辺・属性組み合わせ・新着販売・別商品種・市場の空白・大市場・通年の進行を確認します。候補が足りなければ次の角度へ進み、同じキーワードは再検索しません。
6. 最終結果の3レーンを確認します。`今回イベント` は今回のA/B判定、`エバーグリーン` は通年候補、`季節参考` は次回候補用です。季節参考は今回のA/B件数に含みません。

週次のA/B目標を確保するか、6つの探索角度をすべて確認すると探索は完了します。

## Step 2 候補

Step 2は、Step 1の条件を変えると自動で作られる、次に調査する候補リストです。

- ここは結果ではありません。
- ここに並ぶ候補を、次の3「Etsy公式」で確認します。
- Etsy公式の直近30日検索数、出品数、関連語が絞り込みの土台です。

## Step 3 Etsy公式

Etsy Marketplace Insightsで候補の直近需要を確認します。

- 無料モードは15語、Etsy Plusは入口20語から有望な関連語を5語ずつ追加できます。
- 直近30日の検索数、検索変化率、出品数、関連語を保存します。
- Etsy公式とEverBeeの新しい根拠が揃えば、eRankなしでもA/B候補にできます。
- 数字がUnknown、A/B・B/C境界、関連語不足、季節・国比較、EtsyとEverBeeの矛盾がある場合だけ、Step 5でeRankを追加確認します。

## Step 4 EverBee

EverBeeで売上確認した候補だけが、Step 4に出ます。

- EverBeeは、本当に売れているかを見るために使います。
- Chrome拡張を使う場合、`今回EverBeeで調べるキーワード` に入っている語句だけを調査します。
- 画面外の候補は自動では調査しません。
- 狙い目スコアは、商品化しやすさです。
- Listingsは競合数です。
- Salesは上位商品の月間販売数です。
- Revenueは上位商品の売上です。
- Ageは売れている商品の出品期間です。
- EverBeeの数値は推定であり、自店の実売確定値ではありません。

## Step 5 最終結果・Etsy出品準備

最終結果では次の2スコアを混ぜずに確認します。

- `市場機会スコア`: Etsy公式・EverBeeを中心に需要、競合、販売の広がり、鮮度、リスクを評価
- `商品化・利益スコア`: 買い手意図、参入しやすさ、差別化、販売証拠、利益、時期を100点で評価

市場機会A/Bかつ商品化・利益70点以上は小さく商品化テスト、55〜69点は保留、市場機会Cは派生市場を追加探索、市場機会DまたはIPリスクありは作りません。商品化・利益スコアを編集しても、市場機会スコアは上書きされません。

### 勝ち候補の連続探索

最終結果で `勝ち候補を探す` を押します。画面の探索レールは、需要周辺 → 属性組み合わせ → 新着販売 → 別商品種 → 市場の空白 → 大市場・通年の順です。

- `需要周辺`: 選択市場に近い需要の語を確認します。
- `属性組み合わせ`: 買い手や用途を掛け合わせた語を確認します。
- `新着販売`: 最近売れた商品から得た語を確認します。
- `別商品種`: 同じ需要を別の商品種へ展開して確認します。
- `市場の空白`: 需要に対して競合が薄い語を確認します。
- `大市場・通年`: イベントに依存しない大きな市場を確認します。

選択中のイベントは固定したまま、各角度から最大8件をEtsy公式、EverBeeの順に確認します。別イベントへ自動移動せず、季節参考候補は今回のA/B件数に含めません。

- A/B候補あり: 自動停止し、採用候補を表示
- A/B候補なし: 次の未調査角度へ自動移行
- 拡張機能切断・ログイン待ち・取得制限・外部エラー: 結果を保持して一時停止
- 手動停止・画面再読み込み: 結果を保持し、`探索を再開` から続行

商品化・利益パネルでは、販売価格と費用から算出した1件利益を使い、月5万円・月10万円の必要販売数を表示します。横の推定月間販売数はEverBee推定値であり、到達保証ではありません。

良い候補を3バケットに分けて、Etsyタイトルとタグに変換します。

- Visibilityは、低競合で優先して使いたい語句です。
- Reachは、中競合で検索範囲を広げる語句です。
- Best sellerは、競合は強いが市場の中心になる語句です。

### Etsy Statsを2週間ごとに取り込む

出品後は `validation/research-outcome-template.csv` を使い、2週間ごとに同じlistingの新しいスナップショットを追加します。

1. `snapshotAt`、`listingId`、`visits`、`orders`を入力する
2. 分かる範囲で`revenue`、`netProfit`、表示・クリック・お気に入り・流入元も入力する
3. Step 1の `Etsy Stats CSV` へ貼り付けるか、CSVファイルを選ぶ
4. `内容を確認` の後、`確認した記録を保存` を押す
5. 次の2週間後は同じ`listingId`へ新しい`snapshotAt`を追加する

判定には最新値、推移には全履歴を使います。同じlisting IDと同じ日時だけは後から取り込んだ行で置き換わります。100訪問未満・販売0はWatch、100訪問以上・3販売以上はEarly Go、150訪問以上・販売0は停止・大幅修正候補、クラスター合計300訪問・販売0はクラスター停止候補です。M3は勝ち商品数、M6は実測勝率・注文あたり純利益・CVRを表示します。

## Research Console（デスクトップ専用）

Research Console は幅 1280px 以上を前提にした調査画面です。モバイル用の縦積み画面はありません。狭い表示領域では画面全体を横スクロールして、Queue / Workspace / Inspector の関係を保ったまま使います。

ページ上部のステータスバーには、現在の商品・イベント・年、Chrome拡張の接続状態、実行中サービスとキーワードを常時表示します。停止ボタンは eRank / EverBee または Etsy公式の自動確認が動いている時だけ有効になり、既存の停止処理を呼び出します。

### 5工程タブ

画面上部のタブで、現在の工程だけを Workspace に表示します。

1. 条件: 商品・イベント・年を選び、調査の入口を確定します。
2. 候補: 自動作成された候補を確認し、Etsy公式確認へ送ります。
3. Etsy公式: 候補を Etsy Marketplace Insights で確認します。Etsy 自身が出している数字なので、絞り込みはここを土台にします。
4. EverBee: Etsy公式で絞った候補の販売実績、価格、販売中商品の広がりを確認します。
5. 最終結果: EverBee を含む最終比較、商品化テスト候補、SEO を扱います。

eRank は省略できます。必要な場合だけ、5「最終結果」の `eRankで追加確認` を開きます。

タブの番号色は状態を示します。進行中は teal、完了は green、要確認は amber、次に進める工程は blue、未解放は gray です。失敗した Queue 行だけは red を使います。

### 3列の作業面

- Queue（左、220px）: 工程ごとの候補と状態を絞り込み、語句を選びます。レール内だけをスクロールします。
- Workspace（中央、最小 720px）: 選択中の工程の入力、実行、結果を扱います。工程の長い内容はここだけをスクロールします。
- Inspector（右、320px）: Queue で選んだ語句の由来、数値、判定、失敗内容を確認します。詳細入力は必要なときだけ開きます。

Queue と Inspector は通常工程で常に残ります。最終結果では両方を非表示にして Workspace を 1 列で広げ、比較と出力を読みやすくします。

Console の高さは、上部ステータス、クイックスタート、ステージタブ、下余白を含めた `calc(100vh - 358px)` を基準にします。1280x900、1440x900、1920x1080 で下端をviewport内に収め、Queue / Workspace / Inspector はそれぞれ内部スクロールします。

### 実行状態と出力

各主ボタンの直下には、実行できない理由、待機中の条件、進行状況、完了状態を表示します。黄色の理由表示は入力や前工程が不足している状態、blue は取得中、green は実行可能または完了を示します。

eRank の Queue / Inspector は、Search・Clicks・Competition・KD の4列を基準に、未検索・取得中・一部取得・取得済み・取得失敗を区別します。1列だけ取得できた行は完了にせず、不足列と次の確認先を表示します。数値の判定やEtsy公式へ進める条件は変更しません。

最終結果の「キーワードをコピー」「未来デザイナー用CSV」「参考用eRank CSV」は、結果 Workspace 上部に固定表示されます。長い結果をスクロールしても操作は残ります。

### 表示の基準

白と淡いグレーを基本にし、状態色だけを限定して使います。カード・入力欄・状態ラベルの角丸は 8px 以下で、文字サイズは画面幅に応じて拡大縮小しません。キャッシュ更新後は HTML の CSS と JavaScript が同じ版番号を参照していることを確認します。
