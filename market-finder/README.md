# Market Finder

EtsyMiraiProducerへ組み込む前に、イベント別の低競合キーワード探索を試すための別アプリです。

## できること

- 父の日、母の日、ハロウィン、クリスマスなどのイベントからロングテール候補を生成
- ハロウィンやクリスマスのような大型イベントを、モチーフ・場面・相手・テイスト・周辺需要の5レーンに分解
- Etsy Marketplace Insightsを無料15語、またはEtsy Plusの入口20語＋有望な関連語を最大40語まで段階式で確認
- 広めの市場で売れた商品のタイトル・タグから種ワードを抽出
- `event + target + product + year` を軸に候補を増やす
- Chrome拡張へ直接依頼して、Etsy Marketplace InsightsとEverBee Product Analyticsを順番に確認
- Etsy公式データで先に絞り、EverBeeで売上を確認。eRankは最終結果で不足根拠や関連語を補う時だけ任意で使用
- Etsy公式の需要・供給と、EverBeeで複数商品が売れている広がりを別々に評価
- `Opportunity A-D` と `Confidence High/Medium/Low` を分けて表示
- 古い検索種や一般トレンドは発想用に留め、7日以内のEtsy公式データと45日以内のEverBeeデータをA/B判定に使用。eRankは任意の追加根拠として扱う
- 良い候補を商品テーマ、ターゲット、デザイン方向性、SEOタイトル、タグ案へ変換
- 売れている候補から次ラウンドの派生キーワードを作成
- 高競合でも複数商品が売れている市場から、需要を残しながら競合が下がるクロスニッチを最大3階層まで探索
- 最終結果をイベント固有候補と通年クロスニッチ候補へ分け、別イベントで調査済みの通年市場は後順位へ送る

## 起動

推奨ランチャーは、Market Finderと共有エンジンだけをポート4174で配信します。すでに同じMarket Finderが起動中なら二重起動せず、そのPIDを再利用します。別のプロセスが4174を使用中の場合は、そのプロセスを停止せずに起動を中止します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-market-finder.ps1 -NoBrowser
```

開くURL:

```text
http://127.0.0.1:4174/market-finder/
```

ブラウザも開く場合は `-NoBrowser` を外すか、`start-market-finder.cmd` をダブルクリックします。停止は、PIDとhealth応答がこのMarket Finderに一致した場合だけ行われます。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-market-finder.ps1
```

旧互換のルート `start-market-finder.ps1` と `start-market-finder.bat` は、従来どおりポート4173でeRank・EverBee・Etsyも開く入口として残しています。通常は上記の新ランチャー（4174）を使ってください。

## 3つの使い方と5段階フロー

画面上部の調査方法は次の3つです。

- `自動で探す（おすすめ）`: 条件から候補を作り、5段階で実測する通常モード
- `CSVから判定`: すでに取得済みのEverBee/eRank表を読み込んで判定するモード
- `SEOだけ作成`: 調査済みの良いキーワードからタイトルとタグだけを作る上級者向けモード

`自動で探す` の通常フローは、次の5段階です。

1. `条件`: 商品・イベント・年・探索モードを決める
2. `候補`: 候補を確認し、Etsy公式確認へ送る
3. `Etsy公式`: Etsy Marketplace Insightsの直近検索数・出品数・関連語を確認する
4. `EverBee`: Etsy公式で絞った候補の販売実績を確認する
5. `最終結果`: 2つのスコア、商品化判断、未来デザイナーCSV、SEOを確認する

eRankは必須工程ではありません。最終結果の `eRankで追加確認` は、Etsy中核値が不明、季節・国比較が必要、A/B・B/Cの境界、関連語不足、EtsyとEverBeeの矛盾がある場合だけ使います。Etsy公式とEverBeeの新しい根拠が揃っていれば、eRankなしでもA/B判定を行えます。

### 時期を確認してから複数角度で探索する

イベント商品は、需要ピークの45〜75日前だけを「今作るべき」時期として自動調査できます。早すぎる・遅すぎるイベントでは自動調査を開始しません。続ける必要がある場合だけ `このイベントを続けて調査する` を押して明示的に解除します。

選択したイベントは探索中も固定され、別イベントへ自動移動しません。候補が不足した時は、職業、趣味、贈る相手、ペット、スタイル、買う場面の6つの探索角度を順に切り替えます。同じキーワードは別角度で再調査しません。

週次のA/B目標を確保した時点、または6つの探索角度をすべて確認し終えた時点で、探索は正常に完了します。今回のイベント候補、通年候補、次回用の季節参考候補は別レーンで表示され、参考季節候補は今回のA/B件数に加算されません。

### 勝ち候補が見つかるまで連続探索する

最終結果の `勝ち候補を探す` を押すと、選択中のイベントと商品種別を固定し、職業、趣味、贈る相手、ペット、スタイル、買う場面の順に未調査語を8件ずつ検証します。各回はEtsy公式、EverBeeの順に進み、検証済みA/B候補がなければ次のカテゴリを自動で調べます。通常の上限3階層とは別の連続探索なので、全体の回数上限はありません。

`探索を停止` しても取得済み結果、調査済み語、待機語は消えません。再読み込み後は安全のため一時停止で復元され、`探索を再開` から続けられます。拡張機能の切断、ログイン待ち、取得制限、外部エラー時もデータを保持して一時停止します。A/B候補を見つけた時点で自動停止します。

買い手、職業、趣味、スタイル、贈る相手、ペットの候補は、ニッチ資料をもとに重複と既知のIP語を除いた内蔵カテゴリから生成します。最終結果で1件利益を入力すると、月5万円・月10万円に必要な販売数とEverBee推定月間販売数との比較も表示します。これは目標管理の目安であり、売上を保証するものではありません。

## 2つのスコア

最終結果では、次の点数を混ぜずに並べて表示します。

- `市場機会スコア`: Etsy公式とEverBeeを中心に、需要・競合・販売の広がり・鮮度・リスクを評価する既存の市場判定。Opportunity A〜DとConfidenceを維持します。
- `商品化・利益スコア`: 買い手意図、参入しやすさ、差別化、販売証拠、利益、時期を100点で評価する別の判断軸。市場機会スコアを上書きしません。

最終判断は、市場機会A/Bかつ商品化・利益70点以上なら `小さく商品化テスト`、55〜69点なら保留、市場機会Cなら派生市場を追加探索、市場機会DまたはIPリスクありなら作らない、です。

## 今月の探索モード

条件画面では、運用時期に合わせて次の3モードを手動で選びます。選択はこの端末に保存され、Etsy Statsの推奨表示が自動で上書きすることはありません。

- `市場分散`（M1〜M2）: 新しい市場を100%探索
- `併用`（M3〜M4）: 新市場60%・反応市場40%
- `勝ち市場深掘り`（M5以降）: 新市場30%・反応市場70%

## 調査結果の保管

取得したEtsy公式の検索数とEverBeeの販売データは、更新時に `market-finder/archive/` へJSONで自動保管されます。2「候補」の「調査結果を保管する」から手動保存もできます。ブラウザのlocalStorageだけに置くと、サイトデータの消去や別PCへの移動で、消費した調査枠ごと失われるためです。

保管したファイルは次回以降の「購入者語彙の学習」に使われます。Etsy検索語とEverBeeの商品タイトルを人・理由・場面・修飾に分け、同じ人・イベント・商品カテゴリの実測を優先して次の候補を作ります。購入者欄が未指定または自動選択中なら、最も近い市場の購入者実績を最大3件自動入力します。手入力した購入者は上書きしません。詳細は `market-finder/archive/README.md` を参照してください。

保管には静的サーバ経由でのアクセスが必要です。`file://` で直接開いた場合はボタンが無効になります。

## Chrome拡張連携

1. `etsy-chrome-extension` をChromeでLoad unpackedする
2. 拡張のバージョンが `1.37` になっていることを確認
3. 実Chromeで開いているMarket Finderページが自動再読み込みされることを確認
4. 画面上部のかんたんモードで `候補を自動で探す` を押す
5. `Etsy公式確認を自動実行` を押す
6. `EverBeeで売上を確認する` を押す
7. 追加確認が必要な時だけ、最終結果の `eRankで追加確認` を開く

調査開始後は進捗モーダルが開き、現在のキーワード、完了件数、残り件数、完了/停止/エラー状態を確認できます。
モーダル内の `停止` から途中停止もできます。

接続されない場合は、Market FinderがCodex内蔵ブラウザではなく実Chromeで開かれているか確認し、拡張をReloadしてください。自動再読み込みされない場合だけMarket Finderページを一度再読み込みします。

## 大型イベント分解 / Etsy公式段階式プラン

ハロウィンまたはクリスマスを選んで候補を作ると、40候補を5レーンへ8件ずつ配分します。イベント名を含む `Direct` は30%以下、イベント名から離れた `Adjacent` は40%以上を維持し、外部サイトで実際に見つけた語句は `Observed` として表示します。

候補と最終結果は、イベント名・固有モチーフ・固有場面を含む「イベント固有」と、`teacher`、`nurse`、`book lover`などの「通年隣接」に分けます。Opportunity点数は変えず、同じ順位表へ混ぜません。調査済みの通年クラスターはイベントIDと一緒にローカル保存し、別イベントで再登場した場合は削除せず後順位へ送ります。これにより、ハロウィンとクリスマスの両方で同じ一般市場を最初から繰り返し調べる量を減らします。

同時にMarketplace Insightsの調査プランを作ります。無料モードは入口5件・検証7件・予備3件の15語です。Etsy Plusモードは入口20語から始め、最大200語の関連候補プールから5語ずつ、最大40語を追加する段階式の60検索構成です。検索数・掲載数・コンバージョン表示・商品一致・語句の具体性・複数入口からの再発見を評価し、同じ意味の語は1バッチ2語までに制限します。

`Etsy公式確認を自動実行` を押すと、候補を1語ずつ検索し、結果表示を待って直近30日の検索数・検索変化率・掲載数・関連語を保存し、次の候補へ自動で進みます。Etsyが日本語表示でも英語表示でも、「似たような検索ワード / Similar search terms」と「探索のアイデア / Exploration ideas」を自動で切り替え、各行の検索数・検索結果数・コンバージョン表示を統合します。Etsy側の画面変更などで止まった場合は、対象画面を手動で表示して `表示中の結果を取り込む` から復旧できます。

入口結果を10語以上取得すると、`次の5語を追加` が有効になります。最初の5語を終えた後は残りの入口を確認し、その後は5語ごとに再評価します。20語以上を深掘りした後、2ラウンド連続で新しい有望群が増えなければ早期終了します。Plusモードでもアプリが自動でページ送りや連続検索を行うことはありません。

Etsy公式値は取得後7日以内だけOpportunity A/Bの判定に使い、EverBeeの複数商品販売データと組み合わせます。検索需要だけで「売れる」とは判定しません。

## Broad Market Scan

最初に `fathers day shirt` のような広めの検索で売れ筋商品を見て、商品名・タグ・Salesを貼り付けます。
`種ワード抽出` を押すと、`dog dad`、`bonus dad`、`from daughter` のような語句を拾い、`追加語句へ入れる` で候補生成に使えます。

`広め検索語を作る` を押すと、イベントと商品から `fathers day shirt` などの広め検索語を作ります。
Chrome拡張が接続済みなら、`EverBeeで広め調査` でその検索語を順番に調査し、EverBee画面から商品名と商品別の月間販売数・累計販売数・売上・公開後月数を共通IDで取得します。月間販売数順に並べ、公開12か月以内に複数商品で現れる語句を種ワード抽出で優先します。商品別の結合に失敗した場合は、検索結果全体の最大販売数を各商品へ流用しません。

## 高競合市場からのクロスニッチ探索

EverBee競合10,000件以上、Etsy掲載20,000件以上、またはeRank競合50,000件以上でも、複数の商品が売れている場合は直接狙う候補から捨てず、「探索用親市場」として残します。単一の古いベストセラーだけでは親市場にしません。

5段目の最終確定前に、EverBeeの商品別タイトル、Etsy関連語、すでに調査済みの子市場、保存済みの購入者詳細から具体化軸を抽出します。親市場は上位3件、各深さで次の調査へ送る候補は最大8件、深度は最大3です。総当たりではなく、売れ筋証拠が強い上位だけを通常のEtsy公式・EverBee確認へ戻し、不足根拠がある場合だけeRankを追加確認します。

クロスニッチ専用の追加ボタンはありません。未検証候補が見つかると次の調査ラウンドへ追加され、Etsy公式、EverBeeの既存ボタンで順に確認します。eRankは追加確認が必要な場合だけ使います。深度3まで完了または新しい候補がなくなった時点で、初回結果と子キーワードを合わせて最終順位を確定します。親語、ルート語、深さ、具体化軸、親子比較、判定、停止理由はローカル保存と結果CSVへ保持します。

親子の同じ情報源がそろった場合は、次を表示します。

```text
競合減少率 = 1 - 子の競合数 / 親の競合数
需要維持率 = 子の検索数 / 親の検索数
効率改善倍率 = 子の需要競合比 / 親の需要競合比
```

初期の有望条件は、競合50%以上減、需要10%以上維持、効率1.5倍以上、販売商品2件以上です。親子の月販売中央値を比較できる場合は販売維持率15%以上も必要です。EverBee未確認の子は有望確定にせず、需要維持率3%未満または販売維持率15%未満なら次へ進めません。この「探索優先度」は最終の`Opportunity A-D`点数とは別です。

## eRank連携

eRankは通常の5段階に含まれません。Etsy公式とEverBeeの確認後、最終結果の `eRankで追加確認` を開いた時だけ、Chrome拡張がeRank Keyword Toolを開いて対象語を検索します。
画面から取得できた Average Searches、Average Clicks、CTR、Etsy Competition、KD、Trend をMarket Finderへ戻します。
下に表示される Keyword Ideas / Near Matches も読めた範囲で取り込みます。
取得結果は、不明なEtsy中核値、季節・国比較、A/B・B/C境界、関連語不足、EtsyとEverBeeの矛盾を追加確認するために使います。eRank未取得だけを理由に、Etsy公式とEverBeeが揃ったA/B候補を降格しません。
画面構造が変わった場合の保険として、CSV貼り付け・手入力も残しています。

対応している列:

```csv
Keyword,Listings Analyzed,Top Monthly Sales,Top Revenue,Average Price,Listing Age,eRank Search Volume,eRank Clicks,eRank CTR,eRank Competition,eRank KD,eRank Trend,Etsy Searches 30d,Etsy Listings,Etsy Related Terms,Notes,Visible Listing Count,Selling Listing Count,Recent Selling Listing Count,Median Monthly Sales,Median Monthly Revenue,Total Visible Monthly Sales,Top Sales Share,Median Listing Age Months,eRank Checked At,Etsy Checked At,EverBee Checked At,EverBee Product Rows JSON,Cross Niche Parent,Cross Niche Depth,Market Track,Research Event,Research Category,History Cluster
```

`Listings Analyzed` はEverBee側の補助競合指標として段階評価します。500件以下を20点、1,000件以下を18点、2,500件以下を15点、5,000件以下を12点とし、30,000件以上は過密としてA/Bへ昇格させません。ただし、Etsy公式やeRankの競合数の代替、または販売密度の分母には使いません。
詳しい判断基準は `market-finder/DUAL_TOOL_STRATEGY.md` に置いています。


## 最終評価一覧

最終ステップでは、候補ごとにEtsy Marketplace Insights、EverBee、任意で取得したeRankの結果を横並びで比較できます。

- `Unknown`: 提供元を確認済みですが、推定値が表示されていません。0ではありません。
- `未取得`: その提供元をまだ確認していません。
- `取得失敗`: 接続やページ解析に失敗しています。再試行できます。
- `検証済み`: 必要な確認が終わり、総合点を確定できます。
- `採点前`: クロスニッチなどの探索候補です。探索優先度は総合点とは別に表示します。

`選抜済みを自動検証` は、選抜候補に不足している通常工程をEtsy公式、EverBeeの順で確認します。eRankは、最終結果で追加確認が必要と判断した候補だけを任意で確認します。既に取得した結果と過去の調査ラウンドは保持されます。

未来デザイナー用CSVは、Etsy公式とEverBeeで検証した最終結果を渡す正本です。任意eRankが未取得でも、それだけを理由に出力を止めません。`Verification Status`、`Missing Stages`、`Score Type`、`eRank Capture Status`を含め、eRankの有無も区別できます。参考用eRank CSVは、追加確認を実行した場合だけ使います。

## SEOタイトル / タグ設計

Step 5で、調査済みキーワードを3つのバケットに整理できます。

- `Visibility` は低競合で入口にしたい語句
- `Reach` は中競合で検索範囲を広げる語句
- `Best seller` は競合は強いが市場の中心になる語句

`結果からバケット作成` を押すと、EverBee/eRankの数値から自動で振り分けます。`SEO案を作る` で、タイトルは14語以内を目安に商品名を1回だけ入れ、タグは13個以内・各20文字以内に整えます。

## Etsy Statsを2週間ごとに記録

判定は販売保証ではなく、調査順を決めるためのものです。出品後は2週間ごとにEtsy Statsを確認し、`validation/research-outcome-template.csv` へ同じ `listingId` の新しい行を追加します。

1. `snapshotAt` を `YYYY-MM-DD`、`listingId` をEtsyのlisting IDで入力する
2. 必須の `visits` と `orders`、分かる範囲で売上・純利益・表示・クリック・お気に入り・流入元を入力する
3. 条件画面の `Etsy Stats CSV` へ貼り付けるか、CSVファイルを選ぶ
4. `内容を確認` で対象日とlisting IDを確認し、`確認した記録を保存` を押す
5. 2週間後は同じ `listingId` の新しい `snapshotAt` を追加して再度取り込む

判定には各listingの最新値を使い、推移表には過去の全スナップショットを残します。同じ `listingId` と同じ日時の行だけは後から取り込んだ値で置き換わります。100訪問未満で販売0はWatch、100訪問以上で3販売以上はEarly Go、150訪問以上で販売0は停止・大幅修正候補、クラスター合計300訪問で販売0はクラスター停止候補です。M3では勝ち商品数、M6では実測勝率・注文あたり純利益・CVRを確認し、次の探索モードの推奨に使います。20〜50件の実績がたまるまでは、市場機会A/Bの基準を拙速に調整しません。
