# Market Finder 動画スライド用プロンプト出力機能 設計

## 目的

Market Finderの検証済み調査結果から、Etsy・POD初心者向けYouTube動画で使う16:9スライドをGPT Image 2で作成するためのプロンプトを出力する。

この段階ではMarket FinderからOpenAI APIを直接呼ばない。ユーザーが出力されたプロンプトをコピーし、GPT Image 2を利用できる別の画面へ貼り付けて画像を生成する。APIキー管理と画像生成料金をMarket Finderへ持ち込まず、将来の直接生成機能でも再利用できるプロンプト生成部分を先に実装する。

## 成功条件

- 左サイドバーから、既存の結果画面と混ざらない独立した「動画スライド」画面を開ける。
- 現在の調査コンテキストに属する検証済みA/B候補を、総合点順で最大10件選ぶ。
- 1候補につき1枚の候補別スライド用プロンプトを出力する。
- A/B候補がない場合だけ、検証済みC候補を総合点順で最大3件「試作検討候補」として使用する。
- ユーザーが指定した共通プロンプトを設定画面で編集、端末保存、初期値への復元ができる。
- 全体プロンプト、スライド別プロンプト、ナレーション案をコピーまたはMarkdown保存できる。
- Etsy公式値やEverBee推定値の細かな内訳は出力せず、Market Finderの総合点を中心に見せる。
- 売上保証、未取得データの補完、危険なIP語の提案を行わない。
- 既存の調査、採点、CSV、アーカイブ、サイドメニューの動作を変更しない。

## 対象範囲

### 対象

- `market-finder/` の自動調査フローにある最終結果画面
- 左サイドバーの結果サブビュー
- 現在の調査結果から動画用の安全なデータスナップショットを作る処理
- プロンプトの編集、保存、復元、コピー、Markdownダウンロード
- プロンプト生成処理とUIの自動テスト

### 対象外

- OpenAI APIやGPT Image 2の直接呼び出し
- APIキーの入力、保存、課金表示
- Market Finder内でのPNG生成
- PowerPoint、Google Slides、Canvaへの直接出力
- 調査アルゴリズム、Opportunity評価、Confidence、総合点の計算変更
- Etsy公式データ、EverBeeデータ、eRankデータの取得変更

## サイドメニュー

左サイドバーの「結果を見る」に、独立した結果サブビューを追加する。

```text
制作候補
全評価結果
取得失敗
動画スライド
利益計算
eRank追加確認
探索履歴
```

結果サブビューIDは `video-slides` とする。既存の `activeView` の保存・復元方式へ追加し、「動画スライド」を選択している間は他の結果サブビューを表示しない。

## 動画スライド画面

画面は次の4領域で構成する。

### 1. 対象データ

- 選択中のイベントまたはテーマ
- 商品カテゴリー
- 最新確認日
- Verification Status
- 採用したA/B候補数、またはC試作検討候補数
- IP・商標警告により除外した件数

この領域は、どの調査結果がプロンプトへ入るかを生成前に確認するためのものである。候補の手動並べ替えや個別選択は初回実装に含めない。

### 2. 生成操作

主ボタンを「スライド用プロンプトを作る」とする。押すと、その時点の最終結果から新しいスナップショットを作り、すべての出力を再生成する。

古い出力が残っていても自動更新はしない。調査結果が変わった場合は、画面に「調査結果が更新されています。プロンプトを作り直してください」と表示する。これにより、コピー直前に内容が勝手に変わることを防ぐ。

### 3. 出力結果

次のタブまたは明確に分かれた領域を表示する。

- 全体プロンプト
- スライド別プロンプト
- ナレーション案

操作は次を用意する。

- 全体プロンプトをコピー
- 全スライド分をまとめてコピー
- 各スライドを個別にコピー
- ナレーション案をまとめてコピー
- すべてをMarkdownで保存

コピー完了または失敗は、押したボタンの近くへ短く表示する。

### 4. プロンプト設定

動画スライド画面内に「プロンプト設定」を置き、通常時は折りたたむ。

- 共通プロンプトの複数行入力
- 変更内容の自動保存
- 初期プロンプトに戻す
- 未保存状態や保存ボタンは設けない

設定値はブラウザのローカル保存だけに置く。調査アーカイブ、CSV、結果JSONには含めない。空文字は有効な設定として保存せず、初期プロンプトへフォールバックする。

## 候補選定

### 調査コンテキスト

現在選択中の商品カテゴリーとイベント・テーマに一致する最終結果だけを対象にする。別イベント、別商品カテゴリー、過去の参考レーンを混ぜない。

### 選定順

1. Verification Statusが検証済みである。
2. Opportunity評価がAまたはBである。
3. IP・商標警告がない。
4. Market Finder総合点の降順に並べる。
5. 同点時は既存の最終結果順位を維持する。
6. 上位10件まで採用する。

A/B候補が1件以上ある場合、C候補を混ぜない。A/B候補が0件の場合だけ、同じ条件で検証済みC候補を上位3件まで採用し、出力全体で「試作検討候補」と表現する。

IP・商標警告のある候補は、キーワードスライド、商品案、デザイン案から除外する。除外が起きた場合は画面上の対象データ領域に件数だけ表示し、危険語を再掲しない。

## 動画構成

候補数に応じて4〜13枚とする。

1. 表紙
2. 全体結論
3. 候補別スライド。A/Bを最大10件、1ワードにつき1枚
4. 最終スライド

A/BがなくC候補を使う場合は、候補別スライドを最大3枚とする。

### 表紙

- 「○○ニッチをMarket Finderで調査」
- 調査日
- 商品カテゴリー
- Verification Status

### 全体結論

- A/B候補数、または試作検討候補数
- 最上位キーワード
- 最上位の総合点
- 商品化判断
- 最も重要な理由を1文

### 候補別スライド

1候補につき1枚とし、次の要素だけを掲載する。

- キーワード
- Market Finder総合点
- Opportunity評価
- Confidence
- 商品化判断
- 候補になった理由。最大3項目
- 向いている商品、購入者、使用場面
- Hero NounsまたはRelated Nounsから安全に使用できるデザイン要素。最大3件
- 競合、季節性、未確認データ、データの古さなどの注意点。最大2項目

入力データに存在しない項目は作らない。表示に必要でない場合は省略し、判断に必要な欠落だけ「未確認」とする。

### 最終スライド

- 商品案を1つに絞る
- Etsy上で最新状況を再確認する
- 1商品を出品して反応を記録する
- 売上を保証しない旨の注意書き

## 動画デザインルール

- 16:9、1920×1080
- メインタイトルは54〜64pt
- 各スライドのタイトルは40〜48pt
- 本文は28〜34pt
- 注釈でも20pt未満にしない
- 1枚につき1候補または1メッセージ
- 箇条書きは1領域につき最大3項目
- 1行は日本語25文字前後を目安にする
- 文字が多い場合は縮小せず、短くする
- 画面下部20％は字幕用の余白として残す
- 左右7％以上の余白を設ける
- 背景は白または薄いグレー
- 文字は濃いネイビー
- 良い判断は青緑、注意点はオレンジ
- 色は3〜4色以内
- 小さな表、細かなグラフ、大量カードを使用しない
- キャラクターや意味のない人物写真を使用しない
- 商品画像が入力されていない場合、実在しない商品画像を作らない

## 出力データ

### 安全な調査スナップショット

プロンプトへ直接アプリ内部の行オブジェクトを渡さない。動画用途に必要な値だけを持つ新しいスナップショットを作る。

```js
{
  generatedAt,
  context: {
    eventId,
    eventLabel,
    categoryId,
    categoryLabel,
    latestVerifiedAt,
    verificationStatus,
  },
  candidateMode: 'ab' | 'trial-c',
  excludedIpRiskCount,
  candidates: [{
    keyword,
    totalScore,
    opportunityLabel,
    confidenceLabel,
    productDecision,
    verifiedAt,
    reasons,
    productCategory,
    buyer,
    occasion,
    theme,
    heroNouns,
    relatedNouns,
    cautions,
  }],
}
```

Etsy公式値、EverBee推定値、eRank値の細かな数値列はこのスナップショットへ含めない。理由や注意点は既存の判定結果から作り、存在しない事実を補わない。

### 全体プロンプト

設定済みの共通プロンプト内にある `{{MARKET_FINDER_RESULT}}` を、安全な調査スナップショットの読みやすいテキスト表現へ置換する。

プレースホルダーが削除されている場合は、共通プロンプトの末尾に見出し付きで調査結果を追加する。ユーザーの編集ミスにより調査結果が欠落する状態にはしない。

### スライド別プロンプト

共通デザインルールを短い固定ヘッダーとして各スライドへ付け、表紙、全体結論、候補別、最終スライドの掲載内容を個別に出力する。

候補別では、候補ごとの値を明示し、「この文字を正確に表示する」「入力にない数値や商品画像を追加しない」と指示する。候補別プロンプト間で別の候補データを混ぜない。

### ナレーション案

各スライドに対応する20〜40秒程度の短い日本語原稿を出力する。スライド画像には表示しない。断定表現を避け、「調査時点の候補」「検証する価値がある」などの表現を使う。

## Markdown出力

ファイル名は次の形式とする。

```text
market-finder-video-slides-<category>-<event>-<YYYY-MM-DD>.md
```

内容は次の順序にする。

1. 対象調査の要約
2. 全体プロンプト
3. スライド別プロンプト
4. ナレーション案
5. 売上保証ではない旨の注意書き

- Etsy・POD初心者向けYouTube動画のスライド制作者として振る舞う。
- 視聴者が「なぜ候補になったのか」「どんな商品に向いているか」「何に注意すべきか」を短時間で理解できるようにする。
- 売上を保証しない。
- スマートフォン視聴を想定する。
- `{{MARKET_FINDER_RESULT}}` を入力位置として持つ。
- 表紙、全体結論、1ワード1枚の候補別スライド、最終スライドで構成する。
- A/B候補を最大10件扱う。
- Etsy公式値やEverBee推定値の細かな内訳を並べず、Market Finder総合点を中心に表示する。

## 状態管理

既存の結果サブビュー状態へ `video-slides` を追加する。

動画機能の状態は、調査本体の状態と分離する。

```js
{
  promptTemplate,
  generatedSnapshot,
  generatedSnapshotFingerprint,
  generatedOutputs,
  copyStatus,
  downloadStatus,
}
```

永続化するのは `promptTemplate` だけとする。生成済み出力は再読み込み後に復元せず、最新の調査結果から作り直す。古いプロンプトが別の調査へ誤って使われることを防ぐ。

## エラーと空状態

- 最終結果が0件: 次に必要な調査工程を案内し、生成ボタンを無効化する。
- 検証済みA/BもCも0件: 「検証済み候補がありません」と表示し、生成ボタンを無効化する。
- A/Bが0件でCを使用: 画面とすべての出力で「試作検討候補」と明記する。
- IP除外後に候補が0件: 危険語を表示せず、利用可能な候補がないことを案内する。
- 調査日がない: 「確認日未確認」と表示する。
- データが古い: 既存の鮮度判定に従い、候補の注意点へ追加する。
- Clipboard APIが使えない: コピー失敗を表示し、テキスト選択は可能なままにする。
- Markdown生成に失敗: 保存失敗を表示し、コピー機能は使えるままにする。
- プロンプトが空: 初期プロンプトへフォールバックする。

## 実装境界

プロンプト生成ロジックは、DOMやグローバル状態を直接参照しない独立モジュールにする。

想定する責務は次の通り。

- 現在の最終結果から対象候補を選ぶ。
- 安全な調査スナップショットを作る。
- 共通プロンプトへ調査結果を挿入する。
- スライド別プロンプトを作る。
- ナレーション案を作る。
- Markdown本文と安全なファイル名を作る。

UI層は、既存の `finalEvidenceRows()` から取得した行と現在の調査コンテキストをモジュールへ渡し、返された表示データを描画する。採点や検証状態をUI側で再計算しない。

## 検証計画

### 単体テスト

- A/B候補を総合点順で最大10件選ぶ。
- 11件以上のA/Bから上位10件だけを選ぶ。
- A/Bが1件でもあればCを混ぜない。
- A/Bが0件の場合だけ検証済みCを最大3件選ぶ。
- 未検証候補を選ばない。
- 別コンテキストの候補を混ぜない。
- IP警告候補を除外する。
- 候補1件につき候補別プロンプトを1件作る。
- Etsy公式値とEverBee推定値の細かな数値をスナップショットへ含めない。
- `{{MARKET_FINDER_RESULT}}` を置換する。
- プレースホルダーがない場合でも調査結果を末尾へ追加する。
- 空の編集プロンプトを初期値へ戻す。
- 欠落項目から事実を作らない。
- Markdownのファイル名に危険な文字を含めない。

### UIテスト

- サイドバーに「動画スライド」が表示される。
- 動画スライド選択時に他の結果サブビューが隠れる。
- 対象データ件数とIP除外件数が表示される。
- 生成ボタンで3種類の出力が表示される。
- 全体、全スライド、個別スライド、ナレーションをコピーできる。
- Markdownを保存できる。
- 編集した共通プロンプトが再読み込み後も残る。
- 初期値へ復元できる。
- 調査結果更新後に再生成案内が表示される。
- 生成不能時にボタンと理由が一致する。

### 回帰テスト

- 既存の結果サブビュー保存・復元テストを更新する。
- 既存の調査フロー、最終結果、採点、CSV、アーカイブの対象テストを実行する。
- `git diff --check` を実行する。

## 将来拡張

直接画像生成を追加する場合は、今回の安全な調査スナップショットとスライド別プロンプトを再利用する。OpenAI API呼び出しはローカルサーバーへ追加し、APIキーをブラウザへ渡さない。直接生成、PNG保存、進捗、再試行、利用料金表示は別の設計・実装単位とする。
