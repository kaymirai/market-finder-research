# Future Designer: 共通読み込みモーダルとプロンプト保存分離

## 目的

ページ遷移中の連打を防ぎ、3Aで現在のキーワードセットと無関係な過去プロンプトが表示されないようにする。

## 共通読み込みモーダル

ルートレイアウト直下にクライアント側のナビゲーション状態管理を置き、アプリ全体で同じ全画面モーダルを使う。

- 同一オリジンの通常の内部リンクを押した直後にモーダルを表示し、画面全体の再操作を止める。
- 修飾キー付きクリック、新規タブ、ダウンロード、ページ内アンカー、同じURL、外部リンクは対象外とする。
- 未保存確認などでクリックがキャンセルされた場合は表示しない。
- URLのパスまたは検索条件が変わったら閉じる。遷移失敗に備えて上限時間でも解除する。
- 現在 `WorkspaceShell` が持つ専用オーバーレイは共通機構へ統合し、二重表示を防ぐ。
- ログインと新規登録はリンク遷移ではないため、フォームの送信状態を共通機構へ通知する。入力不備で送信されなかった場合は表示しない。
- モーダルにはスピナーと「読み込み中…」を表示し、背景操作を遮断する。

## キーワードセット別のプロンプト保存

生成結果には、表示元を一意に判定できる `sourceScopeKey` を保存する。

- 基本プロンプト: `snapshot:<キーワードセットID>` を基準にし、キーワード一覧のフィンガープリントも保存する。
- チャレンジプロンプト: `analysis:<売上分析シグネチャ>` を基準にし、売上分析キーワードのフィンガープリントも保存する。
- 保存先は既存の `prompt_recipes.generation_config` を使い、DBスキーマ追加は行わない。
- 同名のキーワードセットでもIDが違えば別セットとして扱う。
- セットを切り替えたら、選択中のスコープと完全一致する保存結果だけを復元する。
- スコープまたはキーワードのフィンガープリントが違う結果は表示せず、新規生成できる空の状態にする。
- 旧形式のように所属を確定できない保存結果は履歴として保持するが、自動復元しない。
- 新しい生成・途中再開・保存更新では、同じスコープのレシピだけを利用する。
- 基本とチャレンジは別スコープとして維持し、基本のセット切替がチャレンジ履歴を削除することはない。

## 画面上の挙動

- 3Aの「使うキーワードセット」を変更した直後に、前セットの生成カードは消える。
- 一致する保存結果があれば、そのセットのカードだけを表示する。
- 一致する結果がなければ、生成前の件数と生成ボタンを表示する。
- 保存履歴にはセット名と生成元を残すが、履歴の明示的な読込操作なしに現在結果へ差し替えない。

## エラー処理

- レシピ保存に失敗した場合は、既存どおり画面内の生成結果を保持し、再試行可能にする。
- キーワードセットが削除済み、またはURLで指定されたIDが見つからない場合は、別セットの結果を代用せず「売れ筋分析」を選択した空状態に戻す。
- 遷移モーダルの上限時間解除後も画面が変わらない場合は、ユーザーが再操作できる状態に戻す。

## テスト

- 内部リンク、フォーム送信、キャンセル、同一URL、外部リンク、URL変更、タイムアウトについて共通モーダルを検証する。
- `WorkspaceShell` の既存ナビゲーションと未保存確認が共通モーダルと競合しないことを検証する。
- キーワードセットAとBの基本プロンプトが相互に復元されないことを検証する。
- 同名でIDが異なるセット、キーワード変更、売上分析更新、旧形式レシピを検証する。
- 一致する途中保存だけが再開され、一致しないレシピを更新しないことを検証する。
- 対象テスト、全体テスト、lint、build、`git diff --check` を実行する。
