# Market Finder 固定サイドバー設計

## 目的

Market Finderの横並び工程タブと、一括で折りたたまれている詳細情報を、デスクトップ用の固定サイドバーへ整理する。

ユーザーが常に次の2点を把握できる状態を作る。

- 現在どの工程にいるか
- どの結果を見ているか

## 対象範囲

- Market Finderの自動調査画面のみ
- デスクトップ表示のみ
- 調査ロジック、保存データ、採点、外部サービス連携は変更しない
- 既存の5工程の状態と遷移をそのまま利用する

## レイアウト

ヘッダーと現在の調査状態の下を、左サイドバーと右コンテンツの2列にする。

```text
┌─────────────────┬────────────────────────────────┐
│ 今回の目標       │ 選択中の工程または結果           │
│ A/B 1 / 5       │                                │
│                 │ 選択した内容だけを表示             │
│ 調査工程         │                                │
│ 1 条件           │                                │
│ 2 候補           │                                │
│ 3 Etsy公式       │                                │
│ 4 EverBee        │                                │
│ 5 最終結果       │                                │
│                 │                                │
│ 結果を見る       │                                │
│ 制作候補         │                                │
│ 全評価結果       │                                │
│ 取得失敗         │                                │
│ 利益計算         │                                │
│ eRank追加確認    │                                │
│ 探索履歴         │                                │
└─────────────────┴────────────────────────────────┘
```

サイドバーは画面を縦にスクロールしても表示位置を維持する。幅は約240pxとし、右側を調査データ表示に使う。

## サイドバー構成

### 今回の目標

- A/B候補の現在数と目標数を表示する
- 調査中、待機中、完了など現在の状態を短く表示する
- 既存の主操作ボタンはサイドバー上部へ配置する
- 操作できない場合は、ボタン直下に理由を表示する

### 調査工程

既存の5工程を縦に並べる。

1. 条件
2. 候補
3. Etsy公式
4. EverBee
5. 最終結果

各項目には件数または状態を表示する。未到達工程は無効表示にし、現在工程は左罫線と背景色で明示する。

### 結果を見る

「最終結果」が利用可能になった時だけ表示する。次の6画面へ分割する。

1. 制作候補
   - A/B候補
   - 次に作るテーマ
   - 未来デザイナーへの出力
2. 全評価結果
   - 調査した全キーワード
   - 総合点の高い順
   - 推奨、検証待ち、保留、除外、取得失敗フィルター
3. 取得失敗
   - 取得に失敗した候補だけ
   - 失敗工程と再試行操作
4. 利益計算
   - 選択中キーワードの利益シミュレーション
   - 任意機能であることを明示
5. eRank追加確認
   - 検索数、クリック、競合、関連語
   - 通常工程では任意であることを明示
6. 探索履歴
   - 今回のイベント
   - エバーグリーン候補
   - 別季節の参考候補
   - 深掘り履歴と交差キーワード

## 表示ルール

- 初期画面は現在の自動調査工程を表示する
- 「最終結果」を開いた直後は「制作候補」を表示する
- サイドメニューを選ぶと右側の表示を切り替える
- 同時に複数の結果画面を縦に並べない
- 選択中の結果画面は端末内へ保存し、再読み込み後に復元する
- 取得失敗メニューには件数を表示する
- 全評価結果メニューには全件数を表示する
- 利益計算は、全評価結果からキーワードを選んでいない場合に選択方法を案内する

## 既存UIからの変更

- 横一列の5工程タブを削除し、同じボタンを左サイドバーへ移す
- 「任意の詳細分析を見る」という一括折りたたみを削除する
- その内部を「利益計算」「eRank追加確認」「探索履歴」に分ける
- 「取得失敗」は全評価結果のフィルターだけでなく、独立したサイドメニューから直接開ける
- 上部に重複している目標・現在状態・主操作をサイドバーへ統合する

## 状態管理

新しい表示状態として結果サブビューだけを追加する。

```text
activeResultView =
  shortlist
  | all-results
  | failures
  | profit
  | erank
  | exploration
```

調査工程は既存の `activeStage` を引き続き使用する。結果サブビューの変更は調査データや実行状態を変更しない。

## エラーと空状態

- 取得失敗が0件の場合: 「取得失敗はありません」
- 全評価結果が0件の場合: 次に実行すべき工程を表示
- 利益計算の対象が未選択の場合: 「全評価結果からキーワードを選んでください」
- eRank結果が0件の場合: 任意機能であることと開始方法を表示
- 探索履歴が0件の場合: 「探索を実行すると履歴が表示されます」
- 外部サービスが未接続の場合: 現在と同じ接続理由を主操作の直下へ表示

## 見た目

- 既存の白、スレート、ティールを維持する
- サイドバーは操作盤として密度を上げ、右側の結果領域は読みやすさを優先する
- 工程番号は実際の処理順なので維持する
- 結果サブビューには工程番号を付けない
- 新しい装飾やアニメーションは追加しない

## 検証

- 5工程の状態表示とクリック遷移が既存動作と一致する
- 調査中の自動遷移でサイドバーの選択状態が更新される
- 最終結果の6サブビューが1画面ずつ表示される
- 全評価結果が総合点順で全件表示される
- 取得失敗から再試行できる
- 全評価結果で選択したキーワードを利益計算へ引き継げる
- 再読み込み後に工程と結果サブビューが復元される
- ページ全体に不要な横スクロールが発生しない
- 既存の調査、保存、CSV出力、EverBee/Etsy連携テストが通る

## 対象外

- モバイル用サイドドロワー
- サイドバーの開閉機能
- 調査アルゴリズムや採点基準の変更
- 新しい外部サービス連携
- 既存の保存データ形式の破壊的変更
