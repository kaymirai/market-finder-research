# 購入者ニッチの反復ドリルダウン設計

## 目的

Market Finderが `teacher`、`cat mom`、`book club` のような広い購入者語を見つけた時、その語を一律に除外せず、需要・競合・売上を確認してから、必要な市場だけを具体語へ掘り下げる。

掘り下げで得た親語・子語・不採用語と検証値を保存し、次回の候補生成、重複探索の回避、再評価に使う。

## 基本原則

- 広い語でも低競合で複数商品が売れていれば、そのまま最終候補に残す。
- 需要はあるが競合が強い語は、最終候補ではなく「深掘りする親市場」にする。
- 語句を長くすること自体は評価しない。競合減少と需要・売上維持が両立した時だけ改善とみなす。
- 親語と子語は同じデータソース同士で比較する。Etsy需要とeRank競合など、異なる情報源の値を組み合わせて改善判定しない。
- 商標・ブランド・キャラクターなどのリスク語句は、生成時と検証後の両方で除外する。

## 具体化する軸

各段階では、親語に一つの具体化軸だけを追加する。複数軸を一度に足さず、どの追加語が結果を改善したか追跡できるようにする。

| 親市場 | 具体化軸 | 例 |
|---|---|---|
| 職業 | 専門、担当、学年、職場 | `teacher` → `special education teacher`、`second grade teacher` |
| ペット | 種、品種、毛色、飼育背景 | `cat mom` → `maine coon mom`、`black cat mom`、`rescue cat mom` |
| 趣味 | 種目、ジャンル、技法、参加形態 | `book club` → `romantasy reader`、`mystery book club member` |
| 家族 | 続柄、ライフステージ、役割 | `grandma` → `first time grandma`、`baseball grandma` |
| グループ | 担当、所属、場面 | `team` → `softball team mom`、`dance team coach` |

具体語は、次の順で集める。

1. Etsy Marketplace Insightsの関連検索語
2. EverBeeで販売が確認できた商品タイトル
3. 過去の保存済み調査で繰り返し確認された語句
4. 既存の購入者詳細辞書

辞書は探索候補を作るための補助であり、実績が確認されるまでは最終推奨にしない。

## 探索フロー

1. 親語を通常どおりEtsy公式、eRank、EverBeeで検証する。
2. 親語がA/B判定、または低競合かつ複数商品販売ありなら、そのまま候補として残す。
3. 親語が高競合だが需要または販売が確認できる場合、具体化候補を作る。
4. 候補を優先順位順に最大8件選び、通常の検証フローへ戻す。
5. 親子の実測値を比較し、良い子語だけを次の深さの親として残す。
6. 最大深さ3まで繰り返す。
7. 各枝で最も良い親語または子語を最終結果へ渡す。深い語を無条件で優先しない。

深さは、広い親語を0、最初の具体化を1、二回目を2、三回目を3とする。

## 親子比較

既存のクロスニッチ比較指標を共通利用する。

- 競合減少率
- 需要維持率
- 需要対競合効率の改善倍率
- EverBee売上中央値の維持率
- 販売商品数
- 最近販売された商品数

既存の判定基準を初期値として使う。

- 需要維持率3%未満: 需要消失として停止
- 競合減少率25%未満: 絞り込み不足として停止
- 売上維持率15%未満、または販売商品0件: 販売根拠不足として停止
- 競合50%以上減少、需要10%以上維持、効率1.5倍以上、販売商品2件以上: 有望な子語
- 一部の数値だけ確認できた場合: 保留し、不足データの取得対象へ戻す

親語自身がA/Bなら、子語が親語を上回らなくても親語を残す。

## 探索件数と停止条件

- 各深さで調査する新規候補は最大8件
- 最大深さは3
- 同じ語句、同じ親子関係、同じ市場文脈は重複生成しない
- 新しい有望候補がない枝は停止
- 需要消失、競合減少不足、売上消失、リスク語句の枝は停止
- eRankの残り検索枠を超える場合は翌日用キューとして保存し、他の工程を止めない
- ユーザーが停止した場合も、取得済み結果と未検証キューを保持する

## 保存する探索データ

調査アーカイブをバージョン3へ拡張し、`drilldownNodes`を追加する。

各ノードに次を保存する。

- `keyword`
- `rootKeyword`
- `parentKeyword`
- `depth`
- `specificityAxis`
- `source`
- `categoryId`
- `eventId`
- `createdAt`
- `checkedAt`
- Etsy検索数、Etsy掲載数
- eRank検索数、クリック、競合、KD
- EverBee競合、販売商品数、最近販売数、売上中央値
- 親子比較値
- `verdict`
- `stopReason`

同一調査中の途中取得は一つの探索グラフへ更新し、数値が増えるたびに別ファイルを作らない。別の日の再調査は新しい観測として保存する。

保存データは次回以降に次の用途で使う。

- 実績のある具体的購入者を自動選択
- 同じ失敗枝の再生成を防止
- 古い有望語の再取得
- イベント間で共通する常緑ニッチの発見
- 未来デザイナー向けCSVへの探索経路追加

## 画面表示

通常画面は現在の5ステップを維持する。途中経過を長い一覧に増やさない。

- 購入者欄には、採用中の親語または具体語と「そのまま採用」「深掘り中」「過去実績」の状態を表示する。
- 最終結果には、採用語、親語、深さ、具体化軸、親子比較、各サービスの実測値を表示する。
- 探索ツリー全体は折りたたみ式の「探索履歴」に置く。
- CSVには親子関係と停止理由も含める。

## エラーと再開

- 外部サービスの取得失敗はノード単位で記録し、その枝だけ再試行する。
- `Unknown`は失敗と区別し、取得済みの値として保存する。
- ページ再読み込み後も探索深さ、未検証キュー、親子関係から再開する。
- 一つの枝が失敗しても、他の枝の検証を続ける。

## テスト

- 広い親語が低競合・販売ありなら、そのまま残る。
- 高競合で販売がある親語だけが具体化される。
- 深いだけで需要が消えた子語は採用されない。
- 有望な子語だけが次の深さへ進む。
- 最大深さ3、各深さ8件、重複なしを守る。
- 手入力の購入者を自動探索が上書きしない。
- 保存後の再読み込みで同じ探索グラフを復元する。
- 同一調査の途中保存を重複観測として数えない。
- 別日の再調査は再現性の証拠として数える。
- 既存の最終採点、eRank、Etsy公式、EverBee、CSVフローを壊さない。

## 対象外

- AIだけで未観測の犬種・職業・趣味を大量生成すること
- 深い語を無条件に高得点にすること
- eRank、Etsy、EverBeeの異なる母集団を一つの比率として比較すること
- 5ステップUIの全面変更
