# Market Finder 現在ニッチ5件探索・市場状態診断 設計

## 1. 目的

Market Finderの最終結果で、A/B候補が見つからなかった理由を次の3種類に分ける。

1. 需要はあるが競合が強く、細分化を続ける価値がある
2. イベントまたは市場の規模が小さく、別テーマへ移る方がよい
3. データ不足または取得失敗により、まだ判断できない

あわせて、選択した商品カテゴリーの中から、直近30日の販売・需要証拠に基づく「現在のニッチ」を最大5件見つける専用モードを追加する。

本機能は売上を保証しない。A/Bは商品化テスト候補であり、市場状態診断は次の探索判断を助けるための表示とする。

## 2. 合意済み要件

- 新機能は既存の「イベントなし」を暗黙に拡張せず、専用モードとして追加する。
- 対象は最初に選択した1商品カテゴリー内に限定する。
- 「現在」は直近30日を基準とする。
- 季節・イベント型と年間型の両方を対象にする。
- 判定基準は5件確保のために緩めない。
- 5件未満の場合は、職業、趣味、ペット、季節、買い手、用途へ自動で探索範囲を広げる。
- 全探索ルートを使い切っても5件に届かなければ、件数を水増しせず、発見件数と市場状態を表示する。
- EtsyまたはEverBeeの取得失敗や必須データ欠損がある場合、市場規模が小さいと断定しない。

## 3. 調査目的の選択

条件画面に `researchGoal.mode` を選ぶ操作を追加する。

### 3.1 指定イベントを調べる

- 既存のイベント選択を使用する。
- 既存の月間出品目標からA/B目標件数を計算する。
- 選択イベントに一致する候補だけを、そのイベントのA/B達成件数へ数える。

### 3.2 現在のニッチを5件探す

- 商品カテゴリーは通常どおり選択する。
- 内部イベントは `auto-discovery` に固定する。
- イベント選択は無効化し、「季節型と定番型を自動探索」と説明する。
- A/B目標は5件に固定する。
- 直近30日より古い証拠は「現在」の判定に使わない。既存採点がソース別に30日より短い有効期限を持つ場合は、既存の厳しい方を優先する。
- 既存のEtsy、EverBee、採点、アーカイブ処理を再利用する。

調査目的は保存対象とし、再読み込み後も変えない。過去データに目的がなければ `event` として移行し、既存挙動を維持する。

## 4. 現在ニッチ探索フロー

候補探索は次の順序で既存プールを使用する。

1. Etsy関連検索語による需要近傍
2. EverBeeで現在売れている商品タイトル由来の短い買い手検索語
3. 職業
4. 趣味
5. ペット
6. 季節・イベント
7. 買い手、用途、贈答理由による細分化
8. 高需要・高競合市場からのクロスニッチ派生

外部確認は既存どおり最大50件単位で処理する。1バッチ完了後、A/Bが5件未満で、停止理由がなく、未使用候補があれば次のバッチへ自動で進む。

### 4.1 停止条件

- 検証済みA/B候補が5件に到達
- すべての探索角度と再試行を使い切った
- ログイン切れ、サービス利用制限、レート制限などの全体停止
- ユーザーによる停止

取得失敗や全体停止は「探索完了」と見なさない。復旧方法を表示し、復旧後に同じチェックポイントから再開できるようにする。

## 5. ニッチ種別

検証済みA/B候補ごとに次を表示する。

- `seasonal`: 既知イベントの正式語、関連シグナル、季節モチーフのいずれかに一致する
- `evergreen`: 上記に一致しない

種別は商品化可否の点数に加算しない。分類表示だけに使用する。季節型でも直近30日の需要・販売根拠を満たせば現在ニッチへ含める。

## 6. 市場状態診断

市場状態診断は独立した純粋関数で行う。入力は、現在の調査目的、固定された商品・イベント文脈、最終証拠行、探索状態、現在時刻とする。

診断は次の優先順で1件だけ返す。

### 6.1 `opportunities-found` 有望ニッチ発見

条件:

- 現在の調査文脈に属する検証済みA/B候補が1件以上ある

表示:

- 発見件数と目標件数
- 上位候補
- 季節型または定番型
- 最新確認日時
- 5件未満で探索継続可能なら、残り件数

### 6.2 `competition-constrained` 需要あり・競合過密

条件:

- A/B候補が0件
- 未検証と取得失敗が0件
- 強い需要または複数商品の販売実績が確認された候補が1件以上ある
- その候補が既存の `Best seller`、高競合、非常に高競合、競合過密のいずれかに該当する

既存の `classifyKeywordBucket`、需要判定、EverBee競合帯を再利用し、新しい別採点は作らない。

表示:

> 市場はあります。競合が強いため、職業・趣味・ペットなどでさらに細分化する価値があります。

補助表示:

- 需要または販売を確認できた親市場
- 競合帯
- 次に未使用の細分化軸があるか

### 6.3 `small-market` 市場規模が小さい

条件はすべて満たす必要がある。

- A/B候補が0件
- 探索状態が `exhausted`
- 未検証と取得失敗が0件
- 全体停止や再試行待ちがない
- 直接テーマまたは入口語と、関連・細分化語2件以上について、直近30日の需要とEverBee販売証拠がそろっている
- 上記の全確認語で、既存基準による需要支持と複数商品販売支持が確認できない
- `competition-constrained` に該当する親市場がない

固定イベントでは、候補がイベントテーマと意味的に一致することも必要とする。無関係な季節語や別趣味語は市場規模判定の分母へ入れない。

表示:

> このイベントは市場規模が小さい可能性があります。これ以上の深掘りより、別テーマを推奨します。

「市場が存在しない」「絶対に売れない」とは表示しない。

### 6.4 `insufficient-evidence` 判定材料不足

次のいずれかに該当する場合に返す。

- 未検証が残っている
- 取得失敗が残っている
- Etsy需要・競合またはEverBee販売根拠の必須部分が欠けている
- 探索が完了していない
- `small-market` に必要な直接語と関連語の確認範囲を満たしていない

表示:

> 市場が小さいとはまだ判断できません。未取得データを確認してください。

具体的な不足項目と再開操作を表示する。

## 7. 証拠の完全性

市場規模診断に使える行は、次を満たす必要がある。

- 現在の固定調査文脈に属する
- 買い手検索語として適格
- Etsy需要と競合が取得済み
- EverBeeの販売商品数と月間販売中央値が取得済み
- 証拠日時が直近30日以内
- 取得状態が `verified`

一部数値だけ残った過去アーカイブは、候補の参考表示には使えても、市場規模が小さいという診断には使わない。

## 8. 最終結果UI

最終結果の先頭に市場診断ブロックを1つ表示する。

共通表示:

- 市場状態
- A/B発見数と目標数
- 調査した商品カテゴリー
- 指定イベントまたは「現在ニッチ探索」
- 最新確認日時
- 判断根拠を最大3項目

状態別の主操作:

- 有望ニッチ発見: 制作候補へ進む
- 需要あり・競合過密: 細分化探索を続ける
- 市場規模が小さい: 条件画面で別イベントを選ぶ
- 判定材料不足: 未取得・取得失敗を再確認する

現在ニッチ探索では、上位5件を1一覧で表示し、各行に `季節型` または `定番型` を付ける。5件未満なら「確認済み3/5件」のように実数を表示する。

既存のA/B/C/D表、詳細、CSV、動画スライドへの導線は残す。市場診断は既存の採点結果を説明する上位レイヤーであり、採点を上書きしない。

## 9. データモデル

保存状態へ次を追加する。

```js
researchGoal: {
  mode: 'event' | 'current-niches',
  targetCount: 1,
  evidenceWindowDays: 30,
}
```

`targetCount` は正の整数とする。`current-niches` では5に固定し、`event` では既存の月間出品目標から計算した件数を保存する。

アーカイブには診断スナップショットも保存する。

```js
marketOutcome: {
  status: 'opportunities-found'
    | 'competition-constrained'
    | 'small-market'
    | 'insufficient-evidence',
  reasonCodes: [],
  opportunityCount: 0,
  coverage: {
    verified: 0,
    pending: 0,
    failed: 0,
    completeEvidence: 0,
  },
  diagnosedAt: '',
}
```

画面表示時は現在の証拠から再診断し、アーカイブの診断は当時の説明用スナップショットとして扱う。

## 10. コンポーネント境界

### 10.1 市場状態診断モジュール

- 市場状態を純粋関数で返す
- DOM、localStorage、外部サービスへ依存しない
- 既存の採点・バケット分類を入力として利用する

### 10.2 現在ニッチ分類モジュール

- A/B行を季節型または定番型に分類する
- 既知イベントシグナルを利用する
- 採点には影響しない

### 10.3 探索オーケストレーション

- `researchGoal.mode` に応じて目標件数とイベント文脈を解決する
- 既存のmulti-angle探索と50件バッチを再利用する
- 基準を緩める処理は追加しない

### 10.4 UI

- 条件画面の調査目的選択
- 最終結果の市場診断ブロック
- 現在ニッチ上位5件の種別表示
- 停止・復旧メッセージ

## 11. エラーと復旧

- ログイン切れ: 判定材料不足として表示し、ログイン後の再開操作を示す
- レート制限: 次回再試行時刻を示し、small-marketへ分類しない
- 一部キーワードの取得失敗: 取得失敗件数を表示し、再試行対象へ送る
- ブラウザ過負荷: 既存の定期リフレッシュとチェックポイント復旧を維持する
- 5件未達かつ候補枯渇: 実数を残し、市場状態診断に従う

## 12. テスト

### 12.1 市場状態診断

- A/Bありなら `opportunities-found`
- 強需要・高競合・A/Bなしなら `competition-constrained`
- 全探索完了・完全証拠あり・需要販売支持なしなら `small-market`
- 未取得、失敗、未完了、確認範囲不足なら `insufficient-evidence`
- 高競合と小市場が同時候補になる場合、高競合を優先する
- 固定イベントと無関係な語を市場規模診断へ入れない

### 12.2 現在ニッチ探索

- 選択カテゴリーを維持し、イベントを `auto-discovery` に固定する
- 季節型と定番型を同じ探索で候補にできる
- 検証済みA/Bが5件で停止する
- 5件未満でもA/B基準を緩めない
- 未使用探索軸があれば次バッチを自動開始する
- 全探索枯渇後は無限ループしない

### 12.3 保存・互換性

- 調査目的、目標、診断日時を保存・復元できる
- 旧保存データは従来のイベント調査として復元する
- 過去の部分証拠だけでsmall-marketを表示しない

### 12.4 UI

- 調査目的の選択に応じてイベント操作と説明が切り替わる
- 最終結果で4状態の見出し、説明、主操作が一致する
- 現在ニッチ5件に季節型・定番型が表示される
- 5件未満の実数と不足理由が一致する

## 13. 非対象

- 全商品カテゴリーを横断したランキング
- Etsy外の市場を含めた総合トレンドランキング
- A/B閾値の緩和
- 売上保証
- eRankを必須工程へ変更すること
- 新しい別採点モデル

## 14. 受け入れ条件

- ユーザーが最終結果だけを見て、高競合、小市場、判定材料不足を区別できる。
- 高競合市場では追加細分化の価値を表示する。
- 小市場は十分な確認範囲と完全な証拠がある場合だけ表示する。
- 現在ニッチ探索は選択カテゴリー内で直近30日のA/B候補を最大5件返す。
- 季節型と定番型を区別できる。
- 5件に届かなくても候補を捏造せず、自動探索が有限に終了する。
- 既存のイベント調査、採点、CSV、動画スライド、保存データを壊さない。
